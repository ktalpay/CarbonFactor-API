# CarbonFactor API — Codex Cloud Run 02 — 2026-04-30

## Purpose

Add a deterministic transport-boundary contract layer on top of the existing in-memory catalog service without introducing a real HTTP server yet.

This run should prepare CarbonFactor API for a future web framework by defining request/response serialization, HTTP-style status mapping, and error envelopes while keeping the implementation standard-library-only and local-testable.

## Current Repository Context

The `develop` branch already contains:

- Python package baseline
- contract dataclasses
- deterministic error helpers
- in-memory synthetic factor catalog service
- API contract and architecture documentation
- evidence backlog and roadmap
- test-only CI

## Design Decision for This Run

Do not add FastAPI, Flask, Django, database drivers, or web server dependencies yet.

Define a transport boundary with plain Python functions and dataclasses that can later be wired to a real HTTP framework.

## CFA-008 — Local Route Handler Functions

### Objective

Add route-handler-like functions that map dictionary inputs to transport envelopes using the existing catalog service.

These are not real HTTP endpoints yet.

### Required Changes

Create:

```text
src/carbonfactor_api/transport/handlers.py
tests/test_transport_handlers.py
```

### Handler Requirements

Implement functions such as:

- `handle_list_factors(query: dict) -> ResponseEnvelope`
- `handle_get_factor(factor_id: str) -> ResponseEnvelope`

Behavior:

- list/search should call existing catalog service
- get-by-id should call existing catalog service
- invalid filters should map to bad request/validation style error envelope
- not found should map to not-found error envelope
- success should include serialized data

Do not start a server.
Do not add route decorators.
Do not add web framework imports.

### Tests

Add tests for:

- list handler success
- filter handler success
- get handler success
- get missing factor maps to not-found status
- invalid query maps to error status
- output envelope is deterministic

### Completion Criteria

- local handler functions exist
- no real HTTP server
- `python -m pytest -q` passes
- commit created
